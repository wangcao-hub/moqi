# moqi 设计

> 不要我去问。

moqi（默契）是一个极简的个人 agent 框架：它从你的日常里了解你，在合适的时候先开口，越用越懂你。内核是纯 TypeScript，同一份代码跑在电脑和手机上。

本文最早写于 2026-11-20，记录要做什么、为什么、不做什么，随版本更新，现在对应 0.5.0。实现以代码和测试为准。

## 1. 三件事加一条原则

"不要我去问"拆成三件事：

|        | 做什么                                                                                   | 内核里的位置                                         |
| ------ | ---------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 看得到 | 从日历、位置、通知、对话等来源收集信息。每个来源都要用户授权，数据只在用户自己的设备上   | 插件的 `sources`、事件日志                           |
| 懂得多 | 维护用户模型：事实、偏好、习惯、关系、正在做的事，每条带证据和可信度。从日常里学，不靠问 | `memory.ts`、`learn.ts`、`routines.ts`               |
| 说得准 | 主动服务：触发 → 候选提议 → 权衡价值与打扰 → 选送达方式 → 看反馈调门槛                   | `proactive.ts`、`briefing.ts`、`watch.ts`、`todo.ts` |

把三件事串起来的原则：**信任按事情一件一件挣**（`autonomy.ts`）。每一类动作单独有一个阶梯：

```
inform（只告诉）→ suggest（建议，一点就办）→ auto-undo（办了，可撤销）→ auto（默默办）
```

同一类事用户连续同意 3 次，moqi 才问"以后要不要直接办"；被拒一次降回 `suggest`。用户也可以在设置里把普通写工具（不危险、从"先问"开始、上限高于"先问"的）直接设成"直接办"，和阶梯共用同一个等级（`level.changed`）。删除记忆、付款这类动作封顶在 `suggest`，永远先问。

**危险动作**另算：执行命令、改删文件、提交表单、付款、把内容发给别人。MCP 服务器和 A2A agent 提供的写工具默认都是危险工具，每次都问，确认里写明完整参数和原因；只有用户能在设置里放开某一个（或判定它不危险），moqi 不会提议。放开的工具，在这一轮对话读过外部内容（除了 moqi 记下、修改自己状态时的回执，任何工具结果都算，包括读出记忆、待办和托管事务的列表；还有别的 agent 的消息）之后仍要先问；提议附带的危险动作，点"好"后仍要确认；例外是 moqi 自己生成的编程任务卡片，用户点"合并到 main"本身就是确认（`callTool` 的 `confirmed`，只在卡片种类、动作、任务编号和任务状态都对得上时才给）。别的 agent 写进来的记忆、读过外部内容之后记下的事，都带着来源；提示词里只要有这样的记忆，这一轮一开始就算读过外部内容。从文章学到的笔记单独放一节，标明只当资料，这只能降低风险。防的是藏在网页、文件、日历邀请、别人消息里的指令；不防恶意的 MCP 服务器，它本来就以用户的权限运行。

## 2. 借鉴的规则

来自之前一个 Android 个人助理原型的经验：

- **记忆**：同一事实印证 3 次转为长期；短期事实 30 天没再提起就淡出（不删，只是不再进提示词）；新说法和旧事实矛盾时，交给用户裁决，裁决本身也是一条主动提议；忘掉一条之前先确认。提示词里最多 30 条，每条最多 120 字，长期的、印证多的在前。
- **抽取走旁路**：不让主对话同时回答和抽事实。每 3 轮用户发言后另起一次请求，`temperature=0`，一次最多 5 条。
- **托管事务**：到点跑一次，和上次比，有变化才说（或设成每次都说）。用 taugraph 流程执行：检查是只读步骤，发出提议是 `write` 步骤。
- **写操作先确认**：即自主权阶梯的 `suggest` 级。
- **教训**：缺口不在对话框架，在没有一个不随进程一起死的地方。所以 moqi 一开始就有一个常驻的"家"。

## 3. 架构

```
 来源（日历/天气/对话…）──► 事件日志（只追加，唯一事实来源）
                                  │  重放得到状态
        ┌─────────────────────────┼─────────────────────────┐
   用户模型（越用越懂）       主动引擎（何时开口）       Agent 循环（怎么做事）
        └─────────────────────────┼─────────────────────────┘
                     工具 + 托管事务（taugraph 流程）
                                  │
                送达：系统通知 / 每日简报 / 动态 / 对话
```

**事件溯源**：所有状态（事实、托管事务、信任等级、提议）都由事件日志重放得到。日志只追加，换设备、同步、排查问题都只需要这一份文件。

**家与伴侣**：电脑上的常驻进程是"家"，持有数据和调度。家同时在 127.0.0.1 上提供控制台（对话、动态、记忆、设置），网页、命令行和以后的手机都通过它读写，日志始终只有一个写入者。手机（P1）是伴侣：收集信息、接收通知、对话，离线时本机运行，和家端到端加密同步。

**内核不碰 Node API**：`src/core` 和 `src/plugins` 只用 `fetch`、`AbortController` 这类各运行时都有的东西，由架构测试检查。Node 专属的部分（文件、通知、命令行）在 `src/node`。

**对话也是 taugraph 运行**：每轮对话是一次 `taugraph/agent` 运行，每次托管事务是一次 taugraph 流程运行。工具的规矩（参数校验、信任等级、确认、是否读过外部内容、网站授权）都在 `callTool` 里，agent 只负责循环和记录；工具轮数用完时，最后一次模型调用不带工具，让模型用文字作答。每次运行的 trace 交给 `onTrace`，家把它存在 `runs/` 下，保留 30 天，用来排查，以后也用于改了提示词之后回放真实对话。事件日志仍是唯一事实来源，trace 存不下不影响 moqi。

## 4. 主动引擎

提议（offer）有类型、价值（0 到 1）、紧急程度（`now` / `today` / `whenever`）和过期时间。送达规则：

1. 类型被用户关掉（mute）的，不送。
2. 免打扰时段（默认 22:30 到 08:00）只放行 `now` 且价值不低于 0.9 的。
3. 每天最多打扰 3 次（系统通知），用完后其余进动态，等简报带出。
4. 价值低于这一类的门槛，只进动态，不打扰。

门槛从反馈里学：采纳降 0.05（不低于 0.2），拒绝升 0.1，过期没理升 0.03，起始 0.5。

唯一的例外是**用户亲口定的时间**：待办到了用户定的提醒时间，提议带 `userTimed`，直接弹通知，不看静音、门槛、免打扰和每日额度，也不占额度。免打扰和额度管的是 moqi 自己开口，用户定的时间本身就是同意被打扰。晚了半小时以上的提醒（比如电脑睡着了）不再算数，按普通提议过关。

### 心思（reflection）

主动不只是规则触发。用户醒着的时候每两小时一次，以及每次聊完 10 分钟后，moqi 把它知道的（档案、最近的对话、各插件眼下的情况、正在盯着的事、用户对之前提议的反应）交给模型，请它想最多三个点子：

- **帮你做**：一件具体的事，能做成托管事务的就附上动作，用户点一下就办；
- **了解你**：一个问题，每天最多两个，回答直接进对话并立刻学习；
- **看世界**：从新闻源里挑和用户有关的，只能引用插件给出的条目，链接不由模型编造。

点子是普通提议，过同样的关。模型给的价值封顶 0.85，永远打破不了免打扰；只有模型标了"今天不说就晚了"的才可能弹通知，其余放进动态；一周内相同或几乎相同的点子不再提。每次想过都记一条 `thought` 事件，控制台的「moqi 在想」照着它列出每个点子和去向。

### 自学（study）

主动还包括自己变好。用户半小时没说话、又不在免打扰时段时，moqi 每天最多学三次：

- **复盘**：攒够三次新的反应后，把每类提议的接受、拒绝、没理和最近的失败交给模型，总结能照着做的经验，撤掉被推翻的旧经验，最多留 12 条；
- **读书**：没什么可复盘时，按档案挑一个主题，读信息源列出的一两篇原文，记下带出处的笔记，最多留 60 条。插件只读自己列出的链接，模型没法指使它访问别的地址。

经验和笔记进入对话和心思的提示词，控制台「记忆」页可以查看和删除。每次学习记一条 `studied` 事件，下次复盘只看那之后的新反应。

### 待办

待办是用户自己要做的事，按天排，可以带一个提醒时间。没做完的自动算作今天的，并标出拖了几天；用户主动改期时重新计算。每晚 21:00（`todoReviewAt`）列出今天还剩的事，这条是 moqi 主动开口，照常过关，而且只在那之后两小时内发。

待办也是 moqi 了解用户、改进自己的材料：

- **听出来的待办**：心思看到对话里提到、但待办里没有的事，问一句要不要记下（`todo.capture`），这一类的门槛单独学；
- **加了三次，第四次不用加**：同一件待办 14 天内排了 3 个不同的日子，就问要不要改成每天提醒，接受后生成一件托管事务；
- **复盘**：完成和删除待办也算用户的反应，攒够了就复盘：哪个时段的提醒管用、哪类事总是拖，总结成经验，进入对话和心思。

### 操作电脑

三个能力包，都要用户在设置里打开：

- **浏览器**：Playwright 的 MCP 服务器，版本固定，用单独的浏览器配置。网站授权：一轮对话里每个网站问一次，之后在这个网站上浏览、点击不再问；输入、填表、上传、执行脚本每次都问。用户可以回答「以后都允许」记住网站（`site.remembered`，只能来自用户在确认框里的回答），设置里可以移除。用户放开的浏览器工具，这一轮读过外部内容后仍能在已授权或记住的网站上继续浏览，到新网站时问网站问题；没读过外部内容时，它直接打开的网站也算这一轮已授权。Playwright 的工具按一张表分成"打开网址"和"在网站里走动"，表里没有的一律按危险工具处理。
- **文件**：只在用户选的文件夹里；路径先解析成真实路径再检查；不覆盖、不改内容、不永久删除，所以每一步都能撤回。移到废纸篓是危险工具。
- **macOS**：几个固定动作加用户勾选的快捷指令；命令直接带参数运行，不经过 shell。每个快捷指令是单独的危险工具，名字取自它的哈希，改名后回到"每次都问"。

- **编程 agent**：把编程任务交给 Kiro CLI 或 Claude Code。每个任务一个分支和一个项目之外的工作区，用户点"合并"之前不碰项目目录。agent 只能改工作区、只能跑用户为项目列出的命令（Kiro 用它的 agent 权限规则，Claude Code 用权限规则加沙箱）；交任务时附上与写代码有关的偏好和经验，确认框里逐条列出。任务进程挂在常驻的家上，moqi 重建时不丢；跑完由当时的 moqi 记下结果、发提议，合并和丢弃是用户的反应，进入复盘。moqi 自己跑的 git 命令不跑任何 hook，免得 agent 写的 hook 在沙箱外运行；Claude Code 不读用户和仓库里的设置，只拿 `~/.claude/settings.json` 里的登录信息。

### 联网搜索

- 查资料走搜索接口，不走浏览器。浏览器读页面要在网页里执行脚本，是危险动作，一轮读过网页之后每次都要确认；一次搜索还要占两三轮工具调用。`web_search` 和 `web_read` 是只读工具，不弹确认；结果算外部内容，之后的危险动作照样要问；托管事务也能用。
- 每家服务一个适配器：DeepSeek 用 Search 和 Fetch 接口（Fetch 在 DeepSeek 的服务器上执行，碰不到用户的局域网）；百度用 AI 搜索，读网页由 moqi 自己下载，只读公网地址，每次跳转重新检查。内核和插件不碰 Node API，看不到域名解析的结果，所以 DNS 重绑定防不住；控制台的接口都要钥匙。
- 这一轮读过外部内容，或者模型能看到的最近 `AGENT.historyMessages` 条消息里来过外部内容（不是 `local` 的工具调用、别的 agent 的消息；记在 `SiteGrant.outsideEarlier`，`tainted` 不变，确认照旧），`web_read` 只读用户和外部给过的网址（用户这次和之前的消息、moqi 之外的工具（插件、MCP、A2A）的结果；不算模型之前的回答、学习笔记、任何记忆、moqi 自己工具的结果（待办、记忆、托管事务，可能是模型前几轮写进去的），也不算工具原样返回的模型自己填进参数的网址），可以更短，不能更长；发出去的是比较时的规范化网址（不带 `#` 后面的部分）。`{ tool, args: { url } }` 形式的调用（`watch_create`）同样检查。读到外部内容之后一轮最多读 5 个网页（`READS_AFTER_OUTSIDE`），挑哪几个读仍是一条很窄的路，只能收窄，不能堵死。拼出来的网址可能把用户的信息带出去，所以不读，也不弹确认，弹了只会让用户习惯点"好"。规则在 `callTool` 里，工具用 `readsUrl` 标记，这一轮出现过的网址和浏览器的网站授权记在同一份每轮记录里。
- 模型是 DeepSeek 时默认打开，用模型的 key：搜索词发给的是对话已经在用的那家，不多一个去处。百度是新的去处，要用户自己选、自己填 key。用户关掉后写进 `search.enabled: false`，之后不再默认打开。
- 打开时，系统提示词「做事的方式」里多一条：先搜、再读，只有要登录、点按钮、填表时才用浏览器。这一条来自插件的 `guide`。
- 不用 DeepSeek 的服务端联网工具：官方说明它是给聊天机器人用的，agent 应该用 Search 和 Fetch 接口。

### 图片

- 用户发的图片和工具带回的图片都存成文件，放在 `<moqi 主目录>/media/<编号>.<扩展名>`，目录 `0700`、文件 `0600`；事件里只记编号（`message.images`）。只收 PNG、JPEG、GIF、WebP，按文件头判断，每张最多 3 MB；浏览器发送前把长边缩到 2048 像素。
- 交给模型时用 OpenAI 的内容数组。最近 3 条带图的用户消息带上图片，更早的、读不到的写成"[图片]"。
- 工具结果可以带图片编号（`ToolResult.images`）：MCP 的 `image` 内容和 macOS 截图会存进媒体，显示在这一轮回答下面，模型只看到"[图片，已显示给用户]"。
- 能不能看图：给模型看一张 32×32 的红色方块，问颜色，答"红"或"red"才算能看；请求本身被拒（400、413、415、422）算看不了，其他错误不算结论。结果记在配置的 `model.vision`，换接口地址或模型名就作废。
- 记忆和复盘只看文字。

### 和其他 agent 协作

- **MCP 服务端**（`moqi mcp`）：其他 agent 读档案、教 moqi、通过 moqi 提醒用户；
- **A2A 服务端**：agent card 加 JSON-RPC，独立钥匙，消息标明来自哪个 agent；
- **MCP 客户端**：用户配置或从其他 agent 那里导入的 MCP 服务器成为 moqi 的工具，只读的随时可用，其余先问；
- **A2A 客户端**：用户添加的 agent 成为 `ask_<名字>` 工具，先问再发。

日志始终只有后台那一个 moqi 在写；协议都是手写的 JSON-RPC，运行时依赖仍然只有 taugraph 和 zod。

## 5. 越用越懂

- **对话抽取**：见第 2 节。
- **习惯识别**：同一个工具在 14 天内的 3 个不同日子、相近的钟点（前后 1 小时）被用户的请求触发，就提议"以后每天这个时候直接告诉你"。采纳后生成一件托管事务。这是"不用问"的最小闭环：用户问了三次，第四次不用问。同样的规则也用在待办上：同一件待办连着几天都加，就提议改成每天提醒。

## 6. 范围

已经做了（0.5.0）：内核；电脑上的常驻进程、控制台和命令行；日历（ICS 文件）、天气（Open-Meteo，免 key）、新闻（RSS/Atom）三个来源；系统通知；每日简报；待办和到点提醒；托管事务；习惯识别；心思和自学；MCP 与 A2A 的服务端和客户端；OpenAI 兼容模型。

下一步（P1）：React Native 手机 App、局域网与端到端加密同步、位置与通知来源。

不做：云服务、多用户、自研卡片渲染、任意脚本（只通过固定动作和用户挑选的快捷指令操作别的 App）。
